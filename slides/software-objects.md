# 객체지향과 캡슐화

소프트웨어 개발 · 핵심 개념 05

객체지향은 상태와 동작을 객체의 책임으로 묶어 설계하는 방식입니다. 캡슐화는 **내부 표현과 변경 규칙을 보호**합니다.

## 왜 필요한가

다른 코드가 내부 상태를 마음대로 바꾸면 지켜야 할 조건이 여러 곳으로 흩어집니다.

---

# 주문 상태 관리

주문 객체가 취소 가능 조건을 확인한 뒤 상태를 바꾸도록 하면, 외부 코드가 상태 값만 임의로 덮어쓰는 일을 줄일 수 있습니다.

## 사례에서 확인할 원리

상속은 코드 재사용만을 위해 선택하지 않습니다. 하위 타입이 상위 타입의 계약을 지킬 수 있는지 확인합니다.
